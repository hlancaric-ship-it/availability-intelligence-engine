Celý tok — deficit, výběr dodavatele, nákupní objednávka, příjem, párování — proběhne v Nexus vrstvě. Shoptet admin zůstává přehledný, e-shop rychlý.

03IZOLACE VRSTVY

Nákupní logika opouští Shoptet admin.

Přesouvá se do dedikované operační vrstvy. Shoptet zůstává rychlý — žádné riziko, že vám složitá logika nákupů zpomalí nebo rozbije obchod.

04MULTI-DODAVATEL

Nikdo nemá celé množství? Systém rozdělí nákup.

6 ks objednáno, primární partner má 4, záložní 2. Nexus navrhne rozdělení, vy schválíte — oba nákupy odejdou automaticky.

Výchozí režim: systém navrhne, vy potvrdíte. Žádný nákup u dodavatele neodejde omylem, dokud ho výslovně neschválíte.

Nasazení

Dva režimy — pro každý Shoptet tarif

Nexus nevyžaduje API. Běží ve dvou plně funkčních variantách — stejná nákupní logika, rozdíl je v tom, jak rychle se data synchronizují se Shoptetem.

Varianta A · Shoptet REST API

Plná automatizace

Pro tarify s API přístupem (Premium). Nexus čte objednávky a skladové stavy přes REST API, navrhuje nákupy u dodavatelů a zapisuje stavy zpět do Shoptetu — bez ručního exportu. Ideální, když chcete co nejkratší prodlevu mezi zaplacením a expedici.

  • Objednávky a stavy v reálném čase
  • Automatická aktualizace stavu v Shoptetu
  • Webhooky při změně objednávky
Varianta B · Bez API

Import / export ze Shoptet adminu

Pro tarify bez API přístupu. Stejný procurement engine — objednávky načtete exportem (CSV/XLSX) ze Shoptetu, Nexus sestaví nákupy a vygeneruje soubory k importu zpět. Dodavatelské feedy a příjmy zboží běží přes plánované CSV cykly.

  • Funguje i tam, kde API vůbec není
  • Export PO a import příjmů u dodavatelů bez API
  • Stejná schvalovací brána a audit trail

API není podmínka. Je to jedna z možností — stejně jako u Pricing Engine. Vyberete režim podle tarifu a toho, jak moc chcete ruční práci eliminovat.

Výjimky & kontrola

Automatika, která ví, kdy má mlčet

Nexus není černá skříňka. Když dodavatel nemá celé množství, feed je zastaralý nebo vznikne nesrovnalost v příjmu — systém vás zastaví a ukáže přesně proč.

Každé rozhodnutí má audit trail: co systém detekoval, jakého dodavatele vybral a co se stalo potom. Ideální pro tým, kde sklad a backoffice musí mít stejný obraz.

  • Rozdělení nákupu mezi 2+ dodavatele, když nikdo nemá celé množství
  • Schvalovací brána před odesláním každé nákupní objednávky
  • Automatická aktualizace stavu v Shoptetu (režim s API) nebo export k importu (bez API)
  • Upozornění na výjimky vyžadující ruční zásah e-shopaře
  • Přehled audit logu — kdo, kdy a proč rozhodl
Upřímně

Co Nexus zatím nedělá

Raději řekneme narovinu, než abyste čekali něco, co systém neslibuje.

Nenahrazuje WMS. Nexus řídí nákup a párování se zákazníky, ne kompletní skladovou logistiku s regály a pickingem.
Neobjednává bez schválení. Výchozí režim je „navrhni a čekej na potvrzení“. Plná autonomie je na roadmapě.
Potřebuje mapování. Bez propojení variant s dodavatelskými kódy systém neví, co kde objednat.
Bez API je to plánovaný sync. Varianta B pracuje s importem/exportem souborů — ne v milisekundách jako REST API, ale se stejnou nákupní logikou.
Závisí na kvalitě feedů. Pokud dodavatel neaktualizuje dostupnost, Nexus pracuje s tím, co má — a upozorní na riziko.
